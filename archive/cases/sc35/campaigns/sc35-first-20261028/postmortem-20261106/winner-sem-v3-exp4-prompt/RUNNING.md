# Запуск сохранённого решения SC35

## Окружение

Измеренный пакет выбирает зарегистрированный харнес `sc35-content` через `candidate/solution.json`. Операторский образ запускает `candidate/solve.py` под Python 3.14 с `lxml==6.1.3` и `jsonschema==4.26.0`. Исходный код находится рядом с открытыми `assets/profile.json` и `assets/taxonomy.json`; веса модели, DOCX-корпус и служебные полномочия в пакет не входят.

Полный запуск требует ту же закреплённую внутреннюю модель `deepseek-ai/DeepSeek-V4-Flash-0731` с `reasoning_effort=max` и доверенный scoped gateway арены. Модель, её параметры, образ и сеть назначаются оператором. Пакет не устанавливает их через пользовательский `solution.json`. Подключение харнеса описано в [инструкции SC35](../../../../../../../cases/sc35/harness/README.md).

## Контракт stdin/stdout

`solve.py` читает один JSON из stdin. Внешний envelope арены содержит `operation=solve`, `uses_model=true`, `input` как строковый JSON текущего примера, `model`, `model_base_url` и положительный `model_request_timeout`. Внутренний `input` содержит ровно `case_id`, `docx_base64`, `document_sha256` и `text_sha256` по штатному контракту SC35. Полный scoped URL является секретом и не должен сохраняться в отчётах или файлах кандидата.

Установленный харнес запускает этот entrypoint с текущим примером. Его stdout содержит одну строку вида `{"answer":"<сериализованный sc35-span-review-v1>"}`. Итоговое schema/coordinate-оценивание выполняет закреплённый пакет метрики арены. Ошибки внешнего envelope, идентичности входа, импорта и transport-пределов дают ненулевой код; в stderr выводится только тип сбоя без содержимого документа или gateway.

Для отдельного технического вызова в подготовленном окружении используйте существующий операторский request-файл с тем же envelope, не создавая новую оценку кампании:

```bash
python -E -s -B candidate/solve.py < operator-request.json > result.json
```

Эта команда выполняет реальную модельную попытку, если request содержит живой gateway. Она приведена как контракт запуска сохранённого метода; подготовка отчёта её не выполняла. Для новой оценки нужны отдельная постановка и разрешённые условия эксперимента.

## Что можно проверить без модели

Исходники, зависимости и формат `solution.json` можно изучать независимо от корпуса. Проекция, `extra_checks.build_review`, отдельные формальные проверки и `merge` являются обычным Python-кодом. Для синтетической проверки полного wrapper можно вызвать `solve(payload, here=..., client_factory=...)` с подставным клиентом, который реализует `complete(messages)` и возвращает корректный JSON для всех переданных assessments. Официальные синтетические проверки baseline/харнеса находятся в `cases/sc35/tests`; они не заменяют проверку качества сохранённого победителя.

Нельзя просто опустить gateway и считать результат измеренным гибридом. `solve.py` создаёт `GatewayClient`, а его конструктор требует корректную конфигурацию до входа в обработчик содержательного этапа. Измеренный fallback на формальный review расположен внутри `review_document` и срабатывает после входа в содержательную проверку, а не превращает неверный внешний envelope в штатный запуск.

## Практические ограничения

Кандидат использует локальные пути только для собственного кода и временного DOCX. Его `README.md` внутри `candidate/` — неизменённый исторический файл предка; точное описание финальной версии дано в документации рядом. Внешнее API массовой проверки, доставка в MLflow и операторские проверки private не входят в код победителя.

Чтобы воспроизвести опубликованный private-балл, недостаточно запустить код на любом DOCX: нужны тот же закрытый набор, профиль, таксономия, каноническая проекция, модель и процедура агрегации. Новая private-серия здесь не создавалась, готовые ответы не повторялись. Изменение констант или исправление описанных эвристик создаёт новую версию и не должно незаметно заменять этот измеренный снимок.

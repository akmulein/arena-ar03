# Победитель SC35 — sem-v3-exp4-prompt

Сохранённое решение `sc35-sem-v3-exp4-prompt` — предложение №34 из 35, родители `sc35-sem-v3-exp3-prompt` и `sc35-formal-exp4`. На private из 640 документов оно получило 92,074036 из 100 и заняло первое место. Код в `candidate/` извлечён из неизменяемого снимка кампании; документация рядом добавлена после завершения поиска и не меняет измеренный метод.

## С чего начать

- [Алгоритм](ALGORITHM.md) объясняет формальные проверки, роль модели, восстановление координат и ограничения.
- [Запуск и зависимости](RUNNING.md) описывает входной контракт и работу через зарегистрированный харнес.
- [Инструкция содержательной модели](candidate/runtime/sc35/arena/skills/espd-content-review/SKILL.md) — точный промпт победителя.

Внешний исследователь кампании работал в Hermes. Сам победитель — программный гибрид `sc35-content`, который вызывает содержательную LLM один раз на документ, а не интерактивный агентский цикл Hermes. Закреплена `deepseek-ai/DeepSeek-V4-Flash-0731` с `reasoning_effort=max`; у метрики LLM-судьи нет.

Отличие от родителя №31 — только `runtime/sc35/extra/extra_checks.py`: перенесены две проверки четвёртой формальной серии, положения номера формулы и префикса номера части. Перечисляющий группы требований промпт унаследован от №14 через №31. Это сочетание расширенного детерминированного набора и конкретной инструкции содержательной модели.

Метод настроен на семейство повреждений одной раскрытой ПМИ. В коде есть постоянные размеров и полей исходной секции, шаблонные заголовки и поля, а также специальное исключение синтетической области. Отсутствие обращений к закрытому эталону и lookup по ID не делает такие проверки универсальными для произвольного DOCX. Высокий private-балл относится к зафиксированному набору и метрике локализации, а не к полной экспертной приёмке ЕСПД.

Результаты готового модельного ответа не повторяются ради качества. При исключении содержательного этапа измеренный код сохраняет инструментальный review; подробности и ограничения этого поведения описаны в алгоритме. Число обращений и токены необходимо брать из доверенного учёта gateway, поскольку собственный флаг `llm_called` после такого исключения может быть `false` даже при выполненной попытке.

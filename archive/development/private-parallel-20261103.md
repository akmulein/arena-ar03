# Параллельный private и сохранение прогресса при обновлении

Пользователь попросил использовать все четыре настроенных слота для private и аккуратно перезапустить текущую серию с сохранением прогресса. Ранее весь принятый private-пакет занимал один слот, а финалисты внутри него выполнялись последовательно. Изменение переводит слот на уровень активного private-финалиста; отдельные train/public-задания продолжают занимать по одному слоту того же общего пула.

Число параллельных финалистов автоматически ограничено `ARENA_EXECUTION_SLOTS`. Другие оценщики с тем же `ARENA_SLOT_DIR` учитываются общими блокировками. У каждого финалиста отдельный учёт судьи и собственный checkpoint; примеры внутри финалиста последовательны. Порядок завершения может отличаться от порядка пакета, а итоговый отбор выполняется после всей серии по прежней метрике, токенам и времени. Модель, профиль runner, данные и принятый пакет не изменяются.

Операторская команда `python -m evaluator.pause --reason ...` сохраняет запрос паузы, привязанный к принятому пакету. Работники завершают активные примеры и сохраняют ответы с расходами, затем серия получает внутреннее состояние `paused`. Во внешнем API пауза отображается как `running`, чтобы исследователь продолжал ожидать результат. `pause_requested` ещё не означает завершённую паузу; перед остановкой контейнера оператор проверяет защищённую запись серии.

Продолжение через `python -m evaluator.resume --reason ... --check` проверяет тот же seal, пакет, окружение, опись checkpoint и сохранённый префикс каждого финалиста. Поддерживается завершение финалистов не по порядку пакета. Основной режим архивирует прежнее состояние и запрос паузы, затем продолжает с первого несохранённого примера каждого финалиста. Существовавший узкий путь восстановления `failed` после поддерживаемой ошибки судейства сохраняется; неизвестные частичные результаты не дают разрешения повторять модельный ответ.

Для старого работающего runtime без `evaluator.pause` требуется отдельный операторский перенос на границе примеров. Замена файлов на диске не меняет загруженный Python-код. Процедура должна завершить активный пример, предотвратить следующий модельный запрос, сохранить исходное закрытое состояние и доказать отсутствие неизвестного прогресса. Расходы остановленной до исполнения технической попытки учитываются отдельно от качества ответов. Развёртывание и фактическое сохранение прогресса текущей кампании проверяются оператором; этот документационный отчёт не заменяет такие свидетельства.

В конфигурации SC-35 выделен отдельный `ARENA_PRIVATE_EVALUATOR_IMAGE` с fallback на прежний `ARENA_EVALUATOR_IMAGE`, чтобы обновление private не пересоздавало остальные сервисы. Для координатора private установлен лимит 24 GiB с учётом одновременного хранения крупных ответов и трейсов. Лимиты одного runner остаются 32 GiB, 8 CPU и 2048 процессов.

В ядро добавлены 30 регрессионных тестов: общий пул слотов, изоляция расхода судей, завершение активных примеров при паузе, восстановление готовых ответов и кандидатов вне очереди, сохранение расходов технической попытки и отказ при неизвестном прогрессе. Существующие проверки узкого восстановления после ошибки судьи сохраняются в последовательном режиме; новый набор отдельно проверяет параллельный режим.

Полные проверки итогового кода прошли: `uv run ruff check .`, `uv run pyright` без ошибок и предупреждений, `uv run pytest` — 1780 тестов за 83,29 с, `uv run python -m evaluator.smoke`. Проверки SC-35 с закреплёнными зависимостями дали 39 успешных тестов. Ruff дополнительно исключает каталоги `archive/cases/**/candidate`: это неизменяемые исторические снимки, обнаруженные обязательной общей проверкой; их исходники не форматировались и не менялись.

Приёмка `tests/docker_private_parallel_smoke.py` прошла на настоящем Docker/GPU6 за 37,666 с без реальных моделей и данных: внешний занятый слот ограничивал private тремя runner, его освобождение запускало четвёртый; затем проверены пауза, продолжение того же пакета, сохранение шести готовых примеров, точное сохранение файла завершённого вне очереди кандидата и прежний public API. Исходный образ отклонил эту проверку из-за последовательного выполнения. Приёмка также обнаружила и помогла исправить восстановление немодельного DockerRunner: он создаёт технический UUID без модельного ledger. Отсутствие ledger теперь допустимо только для фактически выбранного немодельного харнеса с нулевым расходом; модельные решатели и судьи сохраняют строгую проверку учёта.

Образ `arena-sc35-private-parallel:20261103` построен поверх прежнего evaluator только заменой `service.py` и добавлением актуальных `pause.py`/`resume.py`. Проверка без сетевого доступа и с реальными операторскими mounts только для чтения подтвердила совпадение provenance принятого пакета, прежнего build-окружения и всех десяти квитанций подготовки. Модельные вызовы при этой проверке не выполнялись. Фактическое переключение действующей серии проверено 3 ноября 2026 года в 15:15:21 МСК: работают четыре финалиста и заняты четыре общих слота. Сохранены все 246 готовых ответов, 247 файлов учёта и одна техническая попытка без модельных вызовов, учитываемая отдельно от качества. Новый API и контейнер продолжения используют прежний принятый пакет и замороженный реестр runner; остальные девять сервисов сохранили ID, время запуска и счётчики перезапусков. Статусное ожидание исследователя возобновлено. [Отчёт кейса](../cases/sc35/campaigns/sc35-first-20261028/private-parallel-20261103.md) и [серверное свидетельство](../cases/sc35/campaigns/sc35-first-20261028/evidence/private-parallel-live-20261103.json) фиксируют результат; сама private-серия продолжается самостоятельно.

Независимая проверка после переключения подтвердила 24 новых готовых ответа без ошибок, всего 270 с учётом сохранённого префикса. Все новые модельные вызовы учтены, завершённые записи расхода закрыты. [Свидетельство работы после продолжения](../cases/sc35/campaigns/sc35-first-20261028/evidence/private-parallel-health-20261103.json) не содержит закрытых ответов и оценок.

# Выполнение пользовательского ревью аудитов SC71 и SC35

Источник задачи — пользовательское ревью отчётов `archive/local/sc71-audit-20261103/report.md` и `archive/local/sc35-deep-audit-20261107/README.md`, переданное 10 ноября 2026 года. Рекомендации самих аудитов использованы только для уточнения прямо одобренных пунктов. Пункт SC71 7.2, общий модельный прокси, изменения повторов и таймаутов исключены. Реальные модели, поиск решений и удалённое развёртывание не запускались; зафиксированные кампании не изменяются. Коммиты не создаются.

## Критерии приёмки

| Требование | Проверяемый результат |
| --- | --- |
| Единая нумерация | Журнал выдаёт `solution_id` по порядку регистрации; конфликтующий S-номер и буквенные варианты отклоняются |
| Полная история | Campaign API проверяет зарегистрированный снимок до train/public/build; standalone остаётся доступен для инфраструктурных проверок |
| Public и AUC | Зависимая ветка может дождаться своего score; AUC использует только public и ось всех предложений без baseline, неполнота видима |
| Проверяемые гипотезы | Протокол требует проверить фактическое исполнение механизма и сохранять расхождения с предсказанием |
| Train-подвыборки | Их состав, репрезентативность и зависимость от train отражаются в выводах |
| Каталог подготовки | README и таблица происхождения, совместимости, расходов и использования; проверка build → публикация → чтение |
| Делегирование и поиск | Независимые идеи, fork/fresh, вложенные агенты, широкие допустимые механизмы и интернет; 1000/1000 дочерних задач и глубина 10 в Hermes |
| Память и плато | Типизированные статусы методов; преждевременный финал возвращает к альтернативам |
| Параллельная оценка | Несколько примеров одного кандидата используют общий пул; судейские контексты и ресурсы не смешиваются |
| Восстановление | Отдельные стадии примеров сохраняются без квадратичной перезаписи; готовые ответы не генерируются повторно |
| Агрегация | Новые source-пакеты передают только отчёты; старые frozen-пакеты сохраняют прежний контракт |
| MLflow | Компактные квитанции отделены от больших данных; экспорт и чтение файлов потоковые; закрытые результаты не открываются исследователю |
| Ответ и диагностика | Служебная диагностика Hermes не дописывается в оцениваемый ответ |
| Расход исследования | Реальные run/call ID связываются с кандидатами; нераспределённые расходы и неполнота сохраняются явно |
| Ожидание | Локальный wait-any пробуждается по завершению процесса; статус успеха читается из результата проверки |
| Формат ответа субагента | Исправление сериализации использует готовый ответ и ошибки схемы без повторного исследования |

## Исходная проверка

До переноса изменений успешно выполнены `uv run ruff check .`, `uv run pyright`, `uv run pytest -q` (1780 passed) и `uv run python -m evaluator.smoke`. В pytest присутствует существующее предупреждение Starlette о `httpx`.

## Реализация

- [Журнал](../../evaluator/search.py) выдаёт канонический номер и проверяет допуск точного снимка. Старые записи и имена кандидатов сохраняются; новые конфликтующие S-номера и буквенные суффиксы отклоняются. Полный public AUC требует покрытия всего лимита, иначе возвращается явная неполнота и наблюдённый префикс.
- [Атрибуция исследования](../../evaluator/research_usage.py) сверяет реальные run/request ID с gateway ledger, отделяет общие, назначенные, совместные и нераспределённые расходы. Ручные исторические числа обозначены как самоотчёт и не суммируются повторно с доверенным учётом.
- [Сервис](../../evaluator/service.py) и [train](../../evaluator/train.py) исполняют примеры параллельно под общим лимитом слотов; судья получает отдельный контекст. [Checkpoint](../../evaluator/checkpoints.py) сохраняет стадии отдельно, сохраняет порядок набора для агрегации и поддерживает примеры, завершившиеся не по порядку. Полные модельные вызовы остаются в первичных файлах и доступны по ссылкам.
- [Агрегация](../../evaluator/metrics.py) поддерживает `aggregation_input=report`: только идентификатор и отчёт без ответа, ресурсов и истории вызовов. Общая подготовка `freeze_metric` включает этот режим для любого нового пакета, если оператор не выбрал вход явно. Старые frozen/standalone-пакеты без поля сохраняют прежний контракт. Специальные изменения метрик SC35/SC71 сняты.
- [MLflow](../../common/mlflow.md) использует компактные квитанции, отдельные неизменяемые данные, потоковую миграцию и передачу файлов. Экспортированная квитанция не требует перечитывать тяжёлую запись. Общий MLflow принимает только train, а public/private — только закрытый операторский получатель; public-score остаётся в API.
- [Общая интеграция Hermes](../../integrations/hermes/README.md) поддерживает fresh/fork, исправляет формат уже готового результата без инструментов и отделяет диагностику от ответа. Конфигурация — 1000 одновременных и 1000 суммарных дочерних задач, глубина 10. Модель и параметры задаются кампанией. DDGS получает переменную существующего исследовательского сетевого прокси. В `integrations/hermes` находятся общий launcher, образ и проверка сети; они не импортируют кейсы.
- [Общий контроль исследования](../../evaluator/research.py) требует альтернативного механизма и свежего исследователя при преждевременном завершении, работает через адаптер агента и поддерживает пустой private. Числовой детектор плато не вводился. Кейсовые оболочки задают профиль и формат задачи.
- [Событийное ожидание](../../evaluator/wait.py) использует Linux pidfd для уже запущенных процессов. Оно не перезапускает проверки и не принимает завершение процесса за успешную оценку. HTTP-опрос public/private остаётся внутри дешёвого helper, модель ожидает событие.
- [Каталог подготовки](../../preparations/README.md) содержит таблицу происхождения, совместимости, расходов, результатов чтения и использования. Обязательное чтение включено в стартовые инструкции. Протоколы и промпты закрепляют репрезентативные зависимые train-подвыборки, проверку реального механизма, структурированную память методов, делегирование и раунд альтернатив при плато.

## Проверки до переноса общих механизмов

На объединённой рабочей копии прошли `uv run ruff check .`, `uv run pyright`, `uv run pytest -q` — 1925 passed, `uv run python -m evaluator.smoke`. Кейсы проверены командой `uv run --with lxml==6.1.3 --with jsonschema==4.26.0 pytest -q cases/sc35/tests cases/sc71/tests` — 251 passed. Зависимости SC35 взяты из его README. Исправлена исходно неполная синтетическая фикстура проверки старого launcher; его код не менялся.

Дополнительный `uv run pyright -p cases/sc71/pyrightconfig.json` прошёл после исправления типизации подставных модулей в сетевом тесте; сам тест повторно прошёл. На настоящем закреплённом Hermes прошли 8 сценариев с локальным подставным gateway: fresh/fork, вложенное делегирование, исправление формата без инструментов и отделение диагностики.

Контейнерная приёмка MLflow прошла для записи 354 088 327 байт с 320 вызовами, одного вызова 309 625 564 байта и 65 SDK-вызовов с 21 вариантом payload. Полное восстановление совпало с источником, идентификаторы стабильны, OOM и перезапусков нет; память клиента и MLflow ограничена 4 GiB, nginx — 128 MiB. Пик контейнера клиента на тяжёлом одиночном scalar вместе с проверкой результата составил 3 781 570 560 байт; это не обещание произвольного payload при меньшем лимите. Свидетельства: [большие записи](review-implementation-20261110-mlflow-large.json), [SDK](review-implementation-20261110-mlflow-sdk.json).

Контейнерная проверка private прошла за 18,947 секунды: 4 общих слота, 6 кандидатов по 3 примера, 13 уже завершённых примеров сохранены без изменения, готовый кандидат и принятый пакет сохранены. После паузы продолжена та же серия. Один public-кандидат одновременно исполнил 3 примера; отдельно проверено сохранение примера 2 раньше примеров 0 и 1. Модельных обращений нет. [Результат приёмки](review-implementation-20261110-private.json). После обновления этого сценария полные Ruff и Pyright проверены повторно; `git diff --check` чистый.

## Исправление области изменений

По уточнению пользователя общие механизмы вынесены из прежних точек подключения под SC71. Размещение общей логики внутри кейса было ошибкой первоначальной реализации. Владельцы runtime, делегирования, диагностики, интернет-проверки и образа теперь находятся в `integrations/hermes`, а контроль продолжения поиска — в `evaluator/research.py`. Все общие проверки перенесены в корневые `tests/`. Кейсовые файлы содержат профиль, адаптер входа, подключение общей реализации и проверки этого подключения. Каталоги `cases/sc35/metric` и `cases/sc71/metric` вновь совпадают с исходной ревизией.

После переноса на объединённой рабочей копии прошли `uv run ruff check .`, `uv run pyright`, `uv run pytest -q` — 2022 passed, `uv run python -m evaluator.smoke`, `uv run pyright -p cases/sc71/pyrightconfig.json`. Проверки кейсов с зависимостями из README SC35 дали 194 passed; часть прежних кейсовых проверок перенесена в общий набор.

Общий Docker-образ действительно собран без `cases/` и кеша исходников в рабочем образе. В нём прошли CLI `--help` и 8 сценариев закреплённого Hermes с `alternate-synthetic-model` и локальным подставным gateway при отключённой внешней сети. [Свидетельство общей приёмки](review-implementation-20261110-common-hermes.json).

Для старого скрипта проверки сохранён путь `cases/sc71/harness/hermes/config.yaml` как ссылка на общий конфиг. Это совместимый адрес, не самостоятельный профиль: изменяемые настройки находятся только в `integrations/hermes/config.yaml`. Оба кейсовых Docker-рецепта создают такую же ссылку; 7 дополнительных целевых проверок прошли, включая исполнение команд подключения в контейнере без сети и замену старого обычного файла SC35. Ruff, Pyright для SC71 и `git diff --check` повторно прошли. Поведение повторов и таймаутов не менялось, замороженные скрипты кампаний не редактировались.

## Границы результата

Изменения находятся в рабочей копии, без коммитов и без удалённого развёртывания. Новые source-пакеты и настройки предназначены для следующей подготовки; frozen-кампании не переписывались. Реальные модели и реальные датасеты не использовались.

Восстановление сохраняет принцип одного корректного ответа: стадия `solved` до начала судьи допускает продолжение; неизвестный прогресс `solving`, `judging` или агрегации отклоняется. Потоковый JSON-парсер ограничивает память буфером и крупнейшим отдельным scalar, а не всей записью; файловый API не требует восстанавливать огромный Python-объект. Устаревшие уже доставленные public-записи на внешнем MLflow автоматически не удаляются.

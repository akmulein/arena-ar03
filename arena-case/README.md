# AR-03 — интеграция с DeepPavlov Arena

Кейс построен на шаблоне DeepPavlov Arena. Содержит программный baseline, адаптеры запуска и оценки, Docker-конфигурацию и замороженный пакет метрики.

## Контракт

**Решатель:** `ways/baseline/solve.py`

Вход через stdin — JSON с полем `input`, содержащим строку JSON вида `{"image_base64":"..."}`. Дополнительно могут передаваться `assets_dir` и `parameters`.

Выход через stdout — JSON `{"answer":"..."}`, где `answer` содержит строку JSON с таблицами.

Максимальная длина `input` — 500 000 символов. Для используемых 19 998 страниц это ограничение проверено.

**Метрика:** `metric/score.py`

Программное сравнение предсказания с GT. Основной score — TEDS; дополнительные показатели сохраняются в statistics. Невалидный ответ получает score=0. Метрика не использует LLM.

## Воспроизведение

Из корня AR-3:

```bash
bash scripts/setup_arena.sh
```

Скрипт скачивает совместимую версию Arena в `$HOME/.cache/ar03-arena`, подключает этот кейс как `cases/ar-03/`, устанавливает зависимости Arena и собирает Docker-образы, если они отсутствуют.

Проверка:

```bash
cd "$HOME/.cache/ar03-arena"
uv run python -m evaluator.smoke
```

Для контейнерной проверки потребуется локальный train-датасет:

```bash
uv run python -m cases.ar-03.container_check --train /path/to/AR-3/data/train
```

Контейнерный тест проверяет идеальный и невалидный ответы, синтетическую таблицу и одну настоящую train-страницу. GT передаётся только оценщику.

## Среда и статус

- Runner: OpenCV + Tesseract 5.3.0, английский OCR.
- Отдельный контейнер программной метрики.
- Замороженный пакет: `campaigns/cp1/metric/`.
- Зафиксированные версии и локальные идентификаторы образов: `campaigns/cp1/environment.json`.
- `freeze/verify` успешно, 10 файлов.
- Локальная контейнерная интеграция проверена; API submit → score и эволюционная кампания пока не запускались.

Docker-образы не опубликованы в реестре. На другой машине они собираются из Dockerfile; локальные image ID не являются ссылками на скачиваемые образы.

# Метрики

TEDS адаптирован из исходной реализации PubTabNet (IBM, Apache-2.0):
https://github.com/ibm-aur-nlp/PubTabNet/blob/master/src/metric.py
Сохранены APTED, unit insert/delete, rename=1 при несовпадении тега или span,
символьный Levenshtein/max length внутри td, знаменатель — max числа потомков
корневого table (без самого корня). Удалены multiprocessing и batch API;
`distance.levenshtein` заменён эквивалентным RapidFuzz Levenshtein.distance.
Структурный режим очищает содержимое td. Для нашего контракта все ячейки td,
таблицы содержат tbody, форматирование текста внутри ячейки не кодируется.

Сопоставление таблиц не использует текст или GT-структуру: Hungarian assignment
максимизирует сначала число пар с IoU >= .5, затем сумму IoU. Для страницы
с M парами знаменатель TEDS = P + G - M: каждая unmatched таблица даёт ноль.
Таким образом пропуски и лишние таблицы штрафуются явно. Итог TEDS — macro
по страницам. Пустая корректная страница против пустого GT получает 1.

F1 ячеек: exact match (r0,r1,c0,c1,нормализованный текст) внутри сопоставленной
пары. Все ячейки unmatched таблиц входят в FP/FN. Итог — micro F1 по страницам.
Числовые ячейки определяются regex (знак, десятичные разделители, необязательный
процент). Accuracy — exact text+span / число числовых GT-ячеек; пропуски ошибочны.
Страница без чисел возвращает null; итог агрегирует только числовые GT-ячейки.
Это точность OCR строк, а не числовая эквивалентность 1.0 и 1.

Время измеряется perf_counter: предобработка, поиск, OCR, сериализуемый результат;
чтение JPEG и метрики не входят. Невалидный результат получает нулевые метрики.

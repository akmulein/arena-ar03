# Общая интеграция Hermes

Это необязательный харнес арены. Он не выбирает кейс, кампанию, модель, набор данных или метрику. Общие `runtime.py`, `delegation.py` и `config.yaml` отвечают за подключение выбранной внутренней модели, fresh/fork-контекст дочерних агентов, исправление формата готового результата и отделение диагностики от ответа. Ограничения делегирования заданы здесь: `max_concurrent_children=1000`, `oneshot_max_children=1000`, `max_spawn_depth=10`. Модель и параметры берутся из условий запуска; наличие интеграции не делает Hermes обязательным для арены.

`researcher.py` подключает Hermes к общему управлению поиском из `evaluator.research`. Продолжение, запрет раннего завершения, переход к альтернативам и ожидание результатов принадлежат арене. Для другого харнеса можно использовать тот же механизм с его фабрикой агента. Кейсовый адаптер задаёт только свой профиль, формат входа и разрешённые инструменты.

## Сборка

```bash
docker build -f integrations/hermes/Dockerfile -t arena-hermes:local .
```

Образ собирается без каталогов `cases/`. Закреплённый Hermes — `86fa9e6ca1de7ee71132d2be0103f3e37d1fa872`, Python 3.14; `uv sync --frozen --extra ddgs` использует upstream lock. При необходимости доступен [кеш исходников](source-cache/README.md). Он используется установщиком и не копируется в рабочий код образа. Общий установщик `install.sh` также используется совместимыми рецептами образов кейсов. `expose_dependencies.py` делает отсутствующие зависимости арены доступными Python-окружению Hermes; пакеты закреплённого Hermes сохраняют приоритет.

BuildKit применяет соседний `Dockerfile.dockerignore`: в контекст допускаются только зависимости арены, общий evaluator, runner и эта интеграция. При сборке отдельным операторским контекстом перенеси этот allowlist в его корневой `.dockerignore`. Каталоги кейсов, закрытые материалы и состояния запусков в образ не включаются.

## Запуск исследователя

Оператор предварительно готовит кампанию и выдаёт её исследователю по [общим правилам](../../common/preparation.md). Пример использует произвольную кампанию без private; пути относятся к разрешённой рабочей копии и выданному исследовательскому доступу:

```bash
python -m integrations.hermes.researcher \
  --model internal-model \
  --credentials-file /run/arena/model-access.json \
  --prompt-file /workspace/runs/my-campaign/start.md \
  --cwd /workspace \
  --journal /search/search.sqlite3 \
  --no-private
```

Модель также можно задать через `ARENA_MODEL`. `--config-file` выбирает явно подготовленный профиль; без него используется общий шаблон. `--parameters-json` может явно передать зафиксированные параметры выбранной модели. Файл доступа содержит `model_base_url` выданного внутреннего gateway, его `api_key` и при необходимости зафиксированные `parameters`; адрес со scoped-доступом и ключ не записываются в профиль на диске. Секреты передаются через защищённый mount. В контейнере команда исследователя уже является entrypoint, поэтому после имени образа достаточно передать её аргументы. Рабочая копия, канонический журнал и разрешённая сеть подключаются оператором; автоматического выбора кампании нет.

При непустом private вместо `--no-private` задаются `--private-url`, `--private-token-file`, `--private-finalists`, `--private-output-count` и `--private-release-id`. Числа и release ID должны совпадать с подготовленной кампанией. Общий controller проверяет readiness и использует только статус private.

## Интернет исследователя

Общий runtime передаёт существующий `HTTPS_PROXY` или `HTTP_PROXY` в `DDGS_PROXY`, если последний не задан явно. Это подключение к настроенному оператором исследовательскому egress. Отдельная служба проксирования модели не создаётся. Решатель и закрытые оценщики сохраняют собственные сетевые границы; публичный поиск предназначен для общих методов и открытых источников.

Приёмочная команда запускает настоящий `web_search` внутри выбранного образа в выбранной сети и требует непустой результат. Она не обращается к модели или датасету:

```bash
python -m integrations.hermes.network \
  --image arena-hermes:local \
  --network my-research-network \
  --model internal-model
```

Для уже существующего egress добавь `--proxy http://research-egress:3128`. Имена сети, образа и адрес не имеют значений, привязанных к кейсу. Если проверка выполняется внутри самого образа, используй `python -m integrations.hermes.network --model internal-model --probe`. Конкретный deployment может дополнительно проверять свои разрешённые и запрещённые адреса.

## Проверки

Общие синтетические проверки интеграции находятся в `tests/test_hermes_*.py` и `tests/test_research_network.py`; они входят в корневой pytest. `python -m integrations.hermes.mock_check --model alternate-synthetic-model` проверяет реальный закреплённый Hermes с локальным подставным gateway и произвольным синтетическим именем модели. Эти проверки не используют реальные модели или кампании. Кейсовые тесты проверяют только подключение профиля, формат входа и соответствующую инфраструктуру.

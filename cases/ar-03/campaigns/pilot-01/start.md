# Пилот AR-03 в изолированном researcher

Эволюцию разрешает только оператор отдельной явной командой. При отсутствии разрешения API возвращает 423; не обходи эту блокировку. Все исследовательские агенты и оркестратор работают только внутри этого контейнера. Не используй хостовый Codex, SSH, Docker daemon, native runner, закрытые данные или артефакты.

Рабочий campaign_dir — cases/ar-03/campaigns/pilot-01; active/campaign.md содержит только актуальные операторские условия. Прочитай AGENTS.md, README.md, cases/ar-03/README.md, preparation.md, metric-description.json и campaign.md этой кампании, затем prompts/start.md. Применяй следующие кейсовые уточнения к общему стартовому промпту: подготовка уже завершена, реализация frozen metric установлена только у оператора; локально доступны её настоящее описание и состав файлов, а не исполняемый пакет. Отсутствие реализации в researcher — обязательная граница безопасности. Не ищи campaign-01/metric, не запускай evaluator.prepare, prepare.md или новую приёмку. Handoff — preparation.md этой кампании. Условия и размер пилота не менять.

Проверь доступный client.py status: перед исследованием необходимы verified=true, authorized=true, max_solutions=4 и отсутствие несовместимых условий. Файлы handoff описывают прежние реальные свидетельства и не заменяют живой допуск API. При 423 или отсутствии допуска остановись; при разрешённом API не требуй доступ к закрытым файлам и не выполняй повторные проверки моделей или инфраструктуры. Лимит — 4 новых предложения, оценивание только на фиксированных 20 train IDs; public/private в пилоте выключены. Исходные train/public/private 500/200/200 остаются неизменными. Baseline уже измерен, не повторяй аудит, benchmark и старые проверки.

Кандидатский код исполняет только штатный DockerRunner на операторском узле. В контейнере исследователя нет весов и Docker socket. Журнал /search/search.sqlite3 доступен только для чтения. Не пытайся писать в него или подменять score. Для регистрации и замеров используй кейсовый client.py: он обращается к операторскому адаптеру над штатными Journal и API Arena.

```sh
/opt/arena/.venv/bin/python cases/ar-03/client.py status
/opt/arena/.venv/bin/python cases/ar-03/client.py propose --directory cases/ar-03/ways/<version> --hypothesis '<hypothesis>' --change '<change>' --stage detection
/opt/arena/.venv/bin/python cases/ar-03/client.py evaluate --candidate <ID из регистрации> --split train
/opt/arena/.venv/bin/python cases/ar-03/client.py result --measurement <measurement из evaluate> --wait --output results/<measurement>.json
/opt/arena/.venv/bin/python cases/ar-03/client.py progress
```

Python клиента — /opt/arena/.venv/bin/python с уже установленным httpx. Системный /usr/local/bin/python не содержит зависимостей Arena; login-shell меняет PATH. Используй явный интерпретатор, не устанавливай зависимости заново и не создавай новое окружение. Реальные модели запускаются только удалённым DockerRunner; локальных весов и библиотек инференса в researcher не требуется.

Оценщик имеет один слот. При 503 с Retry-After клиент evaluate сам ждёт и повторяет техническую отправку того же кандидата; новая версия и новый measurement не создаются. RETRYABLE у result означает, что отправка не подтверждена: вызови evaluate для того же зарегистрированного ID; сервер переиспользует measurement. При возобновлении сначала продолжи такие отправки; уже полученные корректные результаты не оценивай повторно. Затем оцени остальные зарегистрированные версии и используй только оставшийся бюджет по состоянию канонического журнала. NumPy 2.3.5 предоставлен в /codex/research-packages через PYTHONPATH; используй готовый /opt/arena/.venv/bin/python.

Если имеется baseline-reference.json рядом с этим файлом, используй опубликованный оператором CPU train-20 референс для сравнения. Это отдельная оценка неизменённого baseline, она не входит в четыре новых решения и не заменяет результат S01. Не запускай baseline повторно, не используй public/private вместо этого референса.

Создавай варианты в собственных каталогах ways, сохраняй родословную через --parent и регистрируй точный снимок до оценки. Этапы: detection, structure, ocr, end-to-end. Сервер сам выбирает неизменные 20 train IDs и получает оценки из штатного измерителя. Единственный score — TEDS, maximize, [0,1]; диагностические метрики не образуют составную оценку. Не обучай веса, не меняй модели и существенные зависимости без согласования, сохраняй CPU-совместимость.

После четырёх предложений и завершения проверок выбери один результат и передай его ID через client.py finalize --candidate <ID>. Private не используется. Public AUC в этом пилоте отсутствует. Итог — краткие выводы о вычислениях, расходе доступных лимитов подписки и работе эволюционного цикла; неизвестный расход не объявляй нулевым. Skill не создавай.

# AR-03 — пилот только на train

Лимит: 4 предложенных решения, включая неудачные; завершение по исчерпанию лимита либо команде пользователя. Фактический прогресс определяется каноническим журналом; при возобновлении решения, измерения и оставшийся бюджет сохраняются. Единственный итоговый кандидат выбирается по train TEDS и штатному правилу ресурсов при равенстве; это зависимое train-свидетельство, не подтверждение обобщаемости.

Оценивание: прежние фиксированные 20 train IDs в cases/ar-03/_local/evaluation-ids.json внутри researcher. Список перенесён из уже принятого замера без изменения состава или порядка. Состав исходных train/public/private 500/200/200 не меняется. Public и private не участвуют в этом пилоте, их данные, сервисы и результаты не используются. Public AUC отсутствует, train AUC его не заменяет.

Решатель: ar03-program через штатный изолированный DockerRunner Arena, все компоненты CPU. NativeTrainRunner удалён, fallback запрещён. MPS разрешён только для локального доверенного baseline без обхода ограничений песочницы. Штатный evaluator.train использует frozen metric ar03-baseline-teds-v1, установленную только у доверенного оператора; researcher получает её описание и состав в metric-description.json, без реализации. Score=mean(page TEDS), maximize, [0,1]. Веса прежние; Linux ARM64 использует доступный Paddle 3.2.2. MLflow, Hermes и внешние модельные API отключены. Пилот не запускать без новой явной команды пользователя.

Baseline и его эквивалентность уже проверены; не повторять исходные benchmark, аудит, сравнительные замеры и успешно пройденные тесты. Для пилота создавать изменённые версии от ways/baseline, сохраняя происхождение. Допустимы алгоритмические/геометрические эвристики, предобработка, постобработка, адаптивные параметры, восстановление структуры и OCR. Обучение весов запрещено. Замена моделей и существенные зависимости требуют согласования. CPU-совместимость кода сохранять.

Область изменений: собственные каталоги ways/<candidate> и память этого пилота. Метрика, ways/baseline, provenance.json, ядро Arena и README неизменяемы. Исходный AR-03 сохранён во внешнем операторском архиве, недоступном исследователям. Перед любым замером регистрировать точный снимок через общий журнал. Исследовать этапы detection → structure → OCR; все кандидаты ранжируются только по TEDS. Избегать правил под конкретные документы и зашитых ответов.

Журнал внутри researcher: /search/search.sqlite3, только чтение; изменения через client.py и операторский API. Данные внутри researcher: cases/ar-03/_local/train-500.jsonl. Dataset ID: ar03-train-500; conditions ID: ar03-teds-v1-docker-arm64-cpu-train-only. Прежние native/MPS результаты — отдельные исторические свидетельства, не одна серия с Docker CPU. Локальные результат, длительность решателя/метрики, ошибки и родословная сохраняются штатными CLI. Расход исследовательского Codex измерять по доступным достоверным данным подписки; неизвестные токены не объявлять нулевыми. По результатам предложить лимит основной кампании, K и N.

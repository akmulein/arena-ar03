# AR-03 — разрешённый handoff пилота

Рабочая кампания: cases/ar-03/campaigns/pilot-01. Это операторская публикация разрешённой части уже существующих свидетельств, а не новый запуск подготовки или самостоятельное разрешение эволюции. Владелец принял подготовку репозитория и инфраструктуры. Текущий допуск определяется только защищённым операторским API; статический handoff не заменяет verified/authorized и не позволяет обойти fail-closed.

Задача — получить JSON/HTML таблиц по скану страницы, сохранив строки, столбцы, объединения, многоуровневые заголовки и текст ячеек. Baseline: DocLayout-YOLO, SLANet_plus, PP-OCRv6_small_rec, без LLM в решателе и метрике. Происхождение — cases/ar-03/provenance.json и ways/baseline. Контракт входа/выхода реализован в неизменённом solve.py baseline и runtime/ar03_solver/common/schema.py; исходный скан передаётся как image_base64 в JSON envelope ar03-page-v1.

Пилот: 4 зарегистрированных решения, один итоговый кандидат, только прежние фиксированные 20 train IDs. Исходные split 500/200/200 не меняются; public/private выключены. Score — прежний mean(page TEDS), maximize, [0,1]. Detection Precision/Recall/F1, TEDS-struct, Cell F1 и Numeric accuracy — диагностика, не составная метрика. Обучение запрещено; менять модели и существенные зависимости без согласования нельзя. Код кандидатов исполняется только штатным CPU DockerRunner. Все исследователи и оркестратор работают внутри researcher; MPS допускается только для доверенного baseline вне этого поиска.

Frozen package: ar03-baseline-teds-v1, kind=command. Его действительные metric.json и перечень metric.lock.json опубликованы без реализации в metric-description.json рядом с этим handoff. Программы score.py, aggregate.py и runtime метрики установлены только у доверенных оценщиков на хосте. Их отсутствие в researcher обязательно; не копируй пакет, не выполняй локальные freeze/verify и не ищи операторские каталоги. Описание и состав позволяют восстановить договорённость о метрике; фактическое применение и неизменность обеспечивает операторский контур.

Существующее свидетельство сквозной связи: операторский infrastructure-smoke-01/smoke-summary.json, status=FINISHED, одна синтетическая страница, неизменённый ways/baseline, stock DockerRunner, настоящий путь researcher CLI → relay → operator API → stock train HTTP API, frozen scorer/aggregator, mocks=false, evolution=false. Это отдельная техническая проверка, не кандидат пилота и не benchmark качества. Подробный операторский файл не публикуется и недоступен исследователю. Проверка не повторялась при создании handoff.

Последняя уже выполненная проверка researcher перед этим исправлением: 21/21, checked_at=2026-11-20T09:34:38.887795+00:00; источник — существующее защищённое evidence.json оператора. Это историческое подтверждение, не текущий допуск: после изменения доверенного кода старое разрешение отзывается, штатный run проверяет фактическое развёртывание заново. Владелец также ранее подтвердил эквивалентность baseline/адаптера на 20 train-страницах; повторять её не требуется.

Researcher использует AR03_API и /run/secrets/submit-token через существующий client.py. Журнал /search/search.sqlite3 доступен только для чтения; register/evaluate/result/finalize выполняются через API. Секреты, public/private, постраничные закрытые результаты, визуализации и реализация метрики не передаются. Для API-клиента использовать /opt/arena/.venv/bin/python: httpx уже установлен в этом окружении; системный Python в login-shell его не содержит. Новая установка зависимостей не нужна.

MLflow, Hermes, внешние модельные API решателя/оценщика, build-публикации и private-readiness в этом пилоте не используются. Субагенты наследуют согласованные GPT-6.1 Terra/medium. Начни со start.md этой кампании и общего prompts/start.md с указанным уточнением изоляции, прочитай реестр preparations/README.md. Не повторяй prepare.md, аудит, benchmark, проверки моделей и прежние тесты. Skill в этом запуске не создаётся.

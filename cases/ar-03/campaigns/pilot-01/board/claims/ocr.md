# OCR: раздельное распознавание строк ячейки

Статус: untested. Исследователь ocr; отдельный worktree `_local/worktrees/ocr`, исходная Arena-ревизия `7cb90b8884a6c827698c27830d08b4b64594c1bc`; единственная реализация в `cases/ar-03/ways/pilot-ocr`. Регистрацию и все модельные проверки выполняет оркестратор; ID пока отсутствует.

Гипотеза: baseline передаёт весь прямоугольник ячейки в распознаватель одной строки, что теряет текст многострочных заголовков и подписей. У существующего модуля PaddleOCR вход описан как изображение строки: [официальная документация](https://www.paddleocr.ai/v3.3.1/en/version3.x/module_usage/text_recognition.html). Модель, веса и устройство не меняются.

Минимальное изменение: проекция бинарной маски на вертикальную ось обнаруживает несколько отчётливо отделённых строк, не считая длинные линии рамки; промежутки небольшие относительно высоты символа объединяются, чтобы не отделять точки и диакритику. Только уверенно многострочная ячейка делится по серединам промежутков; исходные цветные фрагменты передаются прежнему CPU OCR один раз каждый и соединяются сверху вниз пробелами. Однострочные и неоднозначные изображения сохраняют прежний crop.

Предсказание до реализации: механические тесты показывают две выходные полосы для двух строк, сохранение однострочного crop и точек символов, правильную привязку результатов к ячейкам и явную ошибку при несовпадении числа результатов. Ожидается рост TEDS относительно сохранённого baseline на едином frozen train-20; опровержением пользы будет отсутствие роста общего TEDS или регрессия из-за ложного разделения строк. Это зависимая train-проверка, не доказательство обобщения.

Происхождение: код, модели и зависимости из `ways/baseline`, см. `cases/ar-03/provenance.json`. Прочитаны сохранённый adapted-mps summary и один разрешённый train-трейс `PMC3441004_1.json` для понимания многострочного заголовка; ни тексты, ни ID не переносятся в код. Старые расходы остаются в подготовленном summary: 95.49633241887204 с алгоритма, 102.21100095892325 с процесса, без новых запусков baseline. Реальные модели не запускаются исследователем; public/private и baseline-source отчёты не читаются. Синтетические тесты механики разрешены исключением `common/search-history.md`.

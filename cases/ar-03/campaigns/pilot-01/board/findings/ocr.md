# OCR: передача реализации на регистрацию

Статус: untested по качеству. ID ещё не назначен; регистрирует оркестратор. Финальный кандидат: `/Users/akmulein/AR-3/arena/cases/ar-03/campaigns/pilot-01/_local/worktrees/ocr/cases/ar-03/ways/pilot-ocr`. Родитель — `ways/baseline`, Arena `7cb90b8884a6c827698c27830d08b4b64594c1bc`; происхождение исходников в `cases/ar-03/provenance.json`, гипотеза в `board/claims/ocr.md`. Дальнейшее изменение этого каталога требует согласования с оркестратором до регистрации.

Проверено: написанные до реализации синтетические тесты `tests/test_ocr_lines.py` используют только искусственные компоненты и подставной OCR. Последний результат: `11 passed in 0.10s`; отдельный ruff всего каталога кандидата прошёл. Проверки охватывают двухстрочное разделение с сохранением исходных пикселей и порядка, рамки, точки и мелкие отдельные метки, однострочный и плоский crop, привязку трёх результатов к двум ячейкам, ошибку количества результатов и пустую таблицу без модели. Никакие модели, train-входы или метрика этими тестами не запускались. Полные обязательные проверки Arena перед общей передачей выполняет оркестратор.

Изменение механизма: `runtime/ar03_solver/baseline/ocr.py` добавляет консервативную сегментацию по вертикальной проекции Otsu-маски с удалением рамок только из маски, оценкой высоты компонент и объединением малых промежутков. Неоднозначный crop остаётся прежним. Чистые многострочные crop режутся по серединам промежутков; исходные цветные полосы распознаются прежней CPU-моделью один раз каждая и соединяются сверху вниз. В `structure.py` только унаследованные lint-проблемы: import spacing и `zip(..., strict=False)` без изменения поведения. Остальные файлы runtime, `solve.py` и `solution.json` совпадают с baseline; новые файлы — описание и синтетические тесты.

Основание гипотезы: [официальная документация PaddleOCR](https://www.paddleocr.ai/v3.3.1/en/version3.x/module_usage/text_recognition.html), поля `input_path` и `rec_text`, описывает вход как text line image. Страница прочитана исследователем; установленная версия модели не менялась. Из разрешённых train-свидетельств прочитаны только adapted-mps summary и `PMC3441004_1.json`; конкретные тексты и ID в код не перенесены. Подготовленная базовая оценка и её ресурсы переиспользуются явно, без повторного baseline: TEDS 0.6677288255652927, 95.49633241887204 с алгоритма, 102.21100095892325 с процесса; это прежние, отдельно учитываемые расходы.

Неизвестное: TEDS кандидата, частота срабатывания на frozen train-20, регрессии и фактическая стоимость дополнительных OCR-полос. Нельзя объявлять улучшение до регистрации и единого train-20 замера. Риски: ложное разделение удалённого надстрочного текста, неразделение тесных строк и нестандартных цветов, дополнительное время распознавания. Это общие геометрические эвристики без ID, lookup и обучения; синтетические проверки доказывают исполнение механизма, но не качество.

Результат сравнивать по mean TEDS; ресурсные затраты записать отдельно. Других версий или реальных запусков исследователь не создавал; public/private и baseline-source отчёты не использовались.

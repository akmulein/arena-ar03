## Точечные исправления независимого ревью

Разрешение привязано к состоянию доверенных файлов при запуске процессов; изменение конфигурации или доверенного кода требует перезапуска операторских процессов, а не повторной verify. Новый control не может разрешить работу старого backend. В идентификацию включены Docker State.StartedAt и фактическое время запуска каждого зарегистрированного операторского процесса. Для assets используется единый строгий список прежних восьми файлов моделей; посторонние файлы, отсутствующие модели и симлинки блокируют запуск.

Тест сохранён в cases/ar-03/tests/test_security_review.py, результат — /Users/akmulein/AR-3-operator/runs/pilot-01/private/security/review-valid-permission.json. Флаги --operator и права 0700 не заменяют отдельный аккаунт/VM/host без доступа исследовательских инструментов. Пустой частный журнал и search-readiness основной кампании пока не создавались: её числовые условия намеренно не заданы.

## Исправление границы исполнения: Docker ARM64

Кандидаты теперь запускаются через неизменённые evaluator.train.create_app → make_runner → HarnessRunner → DockerRunner, без callback или native fallback. Образ arena-ar03-runner:arm64-cpu-v1 успешно собран из официального python:3.13-slim-bookworm. Linux ARM64 использует paddlepaddle 3.2.2, torch 2.15.0+cpu и torchvision 0.29.2+cpu; веса и алгоритм прежние. Требования: harness/requirements-linux-arm64.txt. MPS в этот образ не передаётся.

Разрешены только /candidate read-only, чистые /assets с восемью файлами моделей read-only и временный /tmp. Никакие dataset/reference/public/private/operator artifacts, домашний каталог, host env, credentials или Docker socket в кандидат не монтируются. Network=none, UID 10001, rootfs read-only, cap-drop ALL, no-new-privileges; действуют штатные лимиты процессов, памяти и CPU. Отдельная пустая конфигурация Docker CLI исключает автоматическую передачу proxy env хоста в контейнер. Train launcher проверяет состав model-only assets и отсутствие симлинков; без локального Docker socket прекращает запуск. Новое состояние state-docker-arm64-cpu-v1 и conditions ar03-teds-v1-docker-arm64-cpu-train-only не смешиваются с историческими native записями.

Проверены только новые границы: tests/test_docker_isolation.py — 2 PASS. Первая проверка через настоящий DockerRunner подтвердила недоступность искусственных host/public/private/artifact файлов, host env-маркера, proxy env и Docker socket; запрет записи в rootfs/candidate/assets; доступность /tmp; отсутствие capabilities, повышенных привилегий и сетевого доступа. Вторая выполнила три локальные модели офлайн на синтетической таблице: detection/structure/OCR завершились, Paddle=3.2.2, architecture=aarch64. Ни датасеты, ни метрика, ни benchmark, ни эквивалентность и прежние тесты не перезапускались. Свидетельства: _local/docker-isolation.xml, _local/docker-isolation.log, _local/docker-arm64-build.log. Новая проверка изоляции не является запуском эволюции.

Изоляция кандидатского Docker-процесса подтверждена. Физическая изоляция настоящих public/private и закрытых артефактов от самих исследовательских агентов на текущей общей учётной записи с доступом к Docker не обеспечивается контейнером. Поэтому реальные закрытые сервисы и данные здесь не запускались и не переносились. Для их подключения нужен отдельный операторский VM/хост, чьи файловая система и Docker daemon недоступны Codex; исследователю выдаются только ограниченные API. Основная кампания остаётся не готовой до такого контура и ранее отложенных условий.

# Восстановление неполной сетки SLANet

Родитель: разрешённый `ways/baseline` пилота AR-03, исходная ревизия worktree `7cb90b8`. Без обучения, дополнительных зависимостей и замены моделей. Кандидат сохраняет исходные detector/preprocess/OCR и меняет восстановление структуры: дополняет отсутствующие логические позиции и восстанавливает некорректные bbox из соседней геометрии. OCR содержит только техническое уточнение `zip(strict=True)` после прежней проверки длины результатов.

Все валидные bbox сохраняются. Восстановление использует медианные центры строк/столбцов, интерполяцию пропущенных центров с границами таблицы и границы между соседними центрами. Сначала используются ячейки без span; при отсутствии таких свидетельств допускается геометрия spanning-ячеек. При нарушении монотонности центров применяется равномерная сетка с debug-диагностикой. Полная сетка с валидными bbox проходит без изменений. При отсутствии любой валидной геометрии и при несовпадении числа cells/bbox таблица отклоняется прежним способом.

Мотивация — сохранённые train-ошибки неполного покрытия и потенциального отбрасывания одной таблицы из-за одного bbox; конкретные ответы, тексты и Page ID в код не переносились. Геометрия новых crop приближённая: она может включить соседний текст и ухудшить OCR. Добавленные позиции могут отличаться от истинных merged-ячеек. Эффект по TEDS до зарегистрированного замера неизвестен.

`test_geometry.py` содержит пять синтетических проверок с подставной моделью: сохранение валидной сетки, заполнение дырки, восстановление span-ячейки, отсутствие геометрии и несовпадение числа результатов. Реальные модели и датасет эти тесты не вызывают. Регистрация и замер на фиксированном train-20 выполняются оркестратором.
